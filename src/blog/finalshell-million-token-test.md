上周在 Windows 11 22H2 上装了 FinalShell 4.5.6，我准备用它来处理一份接近百万 token 的聊天记录。这份纯文本文件大约几十 MB，测试环境是 16GB 内存的轻薄本连接 2 核 4G 的 Ubuntu 22.04 云主机，我想看看当海量数据涌来时，它的终端显示、文件传输和命令历史记录功能会不会崩溃。

这篇文章就是一次真实压力测试，看完你就能清楚 FinalShell 扛不扛得住海量聊天记录，以及它的性能瓶颈到底在哪里。我们将重点考察终端渲染、文件传输速度和命令历史这三个核心功能，给你一个明确的结论。

先说结论：日常用没问题，但“百万 token 的上下文”这种夸张场景，FinalShell 的终端渲染会先喊累。

## 打分总览

下面是我按三个维度打的分数，后面有每个维度的具体理由。先看表，再聊感受。

| 维度 | 分数 | 一句话短评 |
|------|------|------------|
| 易用性 | 8/10 | 上手快，大文件显示有空间 |
| 稳定性 | 7.5/10 | 连续跑两小时没崩，但历史记录会卡 |
| 文件传输 | 8/10 | 传几十 MB 文件稳，进度显示有点慢 |

看表格可能觉得都还行，但实际用的时候，那种“差一点就卡住”的感觉挺明显。

### 易用性：8/10

FinalShell 的界面布局对普通用户很友好，左边文件树、中间终端、右边监控，基本不用看教程。连接服务器后直接拖文件就能传，新手也能快速上手。

但处理大文本时，终端滚屏会变慢。我试过直接 `cat` 一个 50MB 的文本文件，滑动滚轮时明显掉帧，得等一两秒才跟上。如果你只是偶尔看大文件，问题不大；如果天天这么干，眼睛会累。另外编码问题得注意，乱码的话可以试试 [FinalShell 编码设置方法](/blog/finalshell-encoding-charset-fix/)。

### 稳定性：7.5/10

连续两个小时保持连接、来回传文件、开着命令历史，FinalShell 没有闪退，这点比我预期好。但有个小毛病：命令历史记录多了之后，输入框会卡顿。我开了历史记录功能，攒了大概三百条命令，打字时偶尔延迟半秒。

这不算大问题，但如果你和我一样急性子，可能会烦。历史记录本身的技巧可以参考 [FinalShell 命令历史小技巧](/blog/finalshell-command-history-tips/)，关掉自动保存能缓解卡顿。

### 文件传输：8/10

传一个 45MB 的纯文本文件，从本地上传到服务器，速度稳定在 1.8MB/s 左右，没有中断。进度条显示有点保守，实际传完了进度条还停在一半，多等几秒才跳完成。

下载同样文件时速度差不多，但有时候会卡在 99% 几秒钟。总的来说能接受，毕竟免费工具。传完文件后如果要用 Docker 容器里的环境，可以看 [FinalShell 访问 Docker 容器](/blog/finalshell-docker-container-access/) 这篇。

## 百万 token 到底装不装得下？

严格来说，“装下”分两种情况。第一种是纯文本存在服务器上，FinalShell 只负责传输和显示路径，那完全没问题——文件就是文件，跟 token 数无关。第二种是你要在终端里直接查看或编辑这个文件，那 FinalShell 的终端渲染就成了瓶颈。

我的操作步骤是这样的：

1. 本地生成一个 48MB 的文本文件，放在桌面。
2. 打开 FinalShell，连接云主机，左侧找到目标目录。
3. 直接把文件拖到左侧面板，等待传输完成。
4. 在终端里执行 `wc -l` 和 `du -h` 确认行数和大小。
5. 用 `less` 翻看文件，测试滚动流畅度。

前四步都顺利，第五步用 `less` 往下翻时，每次翻页要等半秒到一秒。如果换成 `cat`，直接卡住好几秒。所以结论是：传输没问题，显示大文件别硬来。

## 常见问题

**问：FinalShell 能处理多大的文本文件？**

传文件本身没限制，但终端里直接查看建议别超过 10MB，否则卡顿明显。大文件用 `less` 分页看，别用 `cat`。

**问：为什么我传文件时进度条不动？**

进度条刷新有延迟，实际可能已经在传了。等十几秒还没变化再检查网络。另外可以看看 [FinalShell 备份会话配置](/blog/finalshell-backup-session-config/) 确保连接稳定。

**问：手机端能用 FinalShell 吗？**

有安卓版，但大文件操作还是建议电脑端。手机端可以看 [FinalShell 安卓 SSH 客户端](/blog/finalshell-android-ssh-client/) 的介绍。

**问：传大文件会占用服务器内存吗？**

传文件主要占带宽和硬盘，内存影响小。但如果你在终端里打开大文件，服务器内存会被吃掉一部分。

![FinalShell 传输大文件时的界面截图](/static/images/photo-1486406146926-c627a92ad1ab.jpg)

总的来说，FinalShell 4.5.6 在 Win11 上处理百万 token 级别的文本，传输环节稳，显示环节弱。如果你只是搬文件，放心用；如果想在终端里直接翻看，准备好耐心。
